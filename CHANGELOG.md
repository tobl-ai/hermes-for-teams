# Changelog

## 1.2.0

- Add opt-in native task branches for independent work in one shared room, with
  targeted controls, isolated snapshots and lightweight question authority.
- Render streaming, edits, final/recovered delivery and native interactions with
  a ledger-validated task label and the original authenticated request anchor.
- Hold resource leases through physical process completion. Persistent Linux
  kernels retain variables while their complete local process tree is suspended
  between cells. Active native tool RPCs compose into the owning cell's lease.
- Add direct-backend Linux supervision before shell startup, authenticated
  request receipts, queued diagnostics, managed/delegated completion acceptance
  and capability-based exact-core compatibility for b200f5bc and aab71346.
- No blanket remote-effect exactly-once or hostile same-UID sandbox claim; unknown
  effects retain reservations. Live activation is a separate owner lifecycle.

## 1.1.1

- Revalidate the unchanged submission-aware core connection on official Hermes
  v0.22.7 (`b200f5bc…`) and main `ed1afb08…`; no new commit allowlist or force patch.
- Expand exact-source apply/backup/idempotence regressions and no-skip native CI
  to both targets while retaining the prior f0d94882 integration baseline.
- Fetch only required fixture trees rather than cloning unrelated partial-source
  refs, preserving shallow CI and credential-free local verification.
- No production core update, plugin installation, Gateway restart or live rollout.

## 1.1.0

- Support the f0d94882 upstream submission-aware finite-admission layout while
  preserving submission identity and routed-profile scope.
- Support the bf0203a7 finite-admission layout independently of the older
  onboarding prerequisite patch.
- Accept unrelated upstream revisions only when packaged connection modules
  match a tested baseline; changed layouts still fail closed.
- Add exact-source apply/backup/idempotence and submission-scope regressions.
- Prepare compatibility CI for old/current layouts and a daily upstream probe.
- No automatic core installation, Gateway restart or runtime activation.

## 1.0.0

- Establish the supported native scheduler and POSIX operator-queue contracts,
  activation procedure, security model and version-pinned compatibility checks.
- Add the real `1fd18277` legacy native-turn connection without newer session
  modules; preserve physical worker lifetime and recursive native follow-ups.
- Add checked source patching with private backups, idempotence, clean-clone
  verification and conflict refusal. Keep the existing modern connection.
- Preserve native capacity across plugin re-registration, isolate reservations by
  profile/event loop and refuse policy changes while work or waiters remain.
- Fix automatic-only `doctor` operation and distinguish configured from verified
  runtime/provider state. Diagnostics do not create a task database.
- Validate heartbeat lease ranges and reject nonfinite/boolean values before
  changing expiry; preserve stale-worker fencing and conservative recovery.
- Fix terminal result validation after large progress streams, while retaining
  the bounded output limit and uncertain-outcome handling.
- Explicitly reject unsupported non-POSIX operator storage/workers before claiming
  jobs. Add OS/Python, patch-application and distribution-build CI lanes.
- Document that stable software is not a 100-user provider/deployment capacity
  certificate, and does not add cross-server placement or operator-tool user ACLs.

## Earlier development versions

The initial public 0.1.0 release provided an explicit operator queue. Development
0.2 added the modern automatic connection and local rollout. Those historical
prerelease artifacts remain identifiable; they are not the current stable target.
